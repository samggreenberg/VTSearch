# `/expscratch/$USER` deletions log

`/expscratch` keeps no snapshots and has no trash, so **a delete there is final**.
This log records what was deleted, when, why it was safe, and how to rebuild
it, so a later session does not go looking for an input that is gone. Add a
file per cleanup, as [below](#how-to-add-an-entry).

Before deleting a directory, run these checks (the second is
[`lessons/2026-08-12-a-launcher-default-outlives-the-directory-it-names.md`](lessons/2026-08-12-a-launcher-default-outlives-the-directory-it-names.md):
a tool's *default argument* counts as reading a path):

1. the study's issue is closed or `solved`, and its report is merged;
2. `git grep` over `scripts/` and `vtscore/` finds no tool whose default reads the
   directory. A launcher's default *output* location is fine; an input is not;
3. no running job writes or reads it;
4. the owner approves the list.

## How to add an entry

**One cleanup per file, in [`scratch-deletions/`](scratch-deletions/).** Name it
`YYYY-MM-DD-short-slug.md`, and start it with a matching
`# YYYY-MM-DD: what went (size, owner-approved)` heading. Then re-run the index
generator:

```bash
python scripts/gates/gen-docs-inventories.py     # refreshes the table below
```

Entries from the same day are listed alphabetically by slug.

### Why one file per entry

This was one file of dated sections, newest first, until 2026-10-26 (#5262), so
two sessions recording deletes at once both inserted a section at the same spot
and conflicted, which is the problem [`LESSONS.md`](LESSONS.md#why-one-file-per-incident)
had and solved the same way. The table below is the one shared part, and it is
generated: on a conflict there, re-run the generator rather than merging rows by
hand.
