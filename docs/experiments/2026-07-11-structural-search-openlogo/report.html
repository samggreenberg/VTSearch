Structural search in the wild

One cropped logo example, 27,083 unstaged photos: how far does the SIFT+VLAD two-stage pipeline get, does 6-DoF alignment beat 4-DoF, and how much does labeling actually buy?

VTSearch's structural embedder (sift_vlad) is a two-stage instance-search pipeline: Stage 1 ranks the whole corpus by cosine over an 8,192-d VLAD aggregation of SIFT descriptors; Stage 2 re-ranks the top-50 by RANSAC-fitting a 4-DoF similarity transform (translation, rotation, uniform scale) from the example's keypoints to each candidate, gated by an inlier score and — once the user votes — a learned match-statistics classifier. The three questions Sam posed map to the three experiments below. Every number comes from real, unstaged photos: OpenLogo aggregates seven logo-detection datasets with per-image bounding boxes, so queries are genuine "logo in the wild" crops, not synthetic marks on clean backgrounds.

TL;DR. ① Seeded with one real-world crop, the structural pipeline finds the rest of a logo's instances only for flat, texture-rich marks — median AP is 0.006, and the bottleneck is Stage-1 VLAD recall (2.5% of true instances reach the top-50), which no amount of Stage-2 geometry or voting can undo. SigLIP cosine on the same crops is ~10× stronger (mean AP 0.31 vs 0.03). ② Moving alignment from 4-DoF to 6-DoF does not improve error rates: it verifies 2.3 pt more true pairs but 5.6× more false pairs, and end-to-end AP is unchanged; 8-DoF homography is strictly worse. ③ For structural detectors, labels are mostly calibration — the trained verification classifier tracks the label-free inlier gate almost exactly — whereas for the MLP-over-SigLIP detector the same 40 votes drive AP from 0.39 to 0.67. Label effort matters roughly 10× more on the deep-embedder path.

EXPERIMENT ASeed one example in the wild — does VTSearch find the rest?

Setup. For 60 brands (every brand with ≥20 tagged photos, sampled across the size spectrum; 3 query seeds each where possible → 175 queries), a simulated user crops one in-the-wild instance to its ground-truth box and uploads it — exactly the production example-sort flow: the crop is re-SIFTed, VLAD-aggregated for Stage 1, and its keypoints become the Stage-2 template. Metrics are computed against every other photo of that brand in the full 27,083-image corpus. Four pipelines score the same queries: Stage 1 alone, the production two-stage, SigLIP cosine on the identical crop, and a hybrid (SigLIP retrieval, structural verification of its top-50).

Finding. "Find the rest of the logos" works only when the mark is large and heavily textured. The binding constraint is Stage-1 VLAD recall — the top-50 shortlist contains 2.5% of the true instances on average, and Stage 2 (any geometry) plus 30 votes can only reorder that shortlist. The hybrid row shows the fix direction: SigLIP retrieval with structural verification inherits SigLIP's recall (0.25 R@50) while keeping the box-overlay explanation. At cold start it doesn't beat SigLIP's AP — verification is too conservative (only ~17% of true pairs verify, below) — but it changes what the user sees: of ~1.4 geometric matches claimed per query, 80% are genuine.

EXPERIMENT B4-DoF vs 6-DoF vs 8-DoF: does richer alignment cut error rates?

Setup. The production matcher fits estimateAffinePartial2D — 4 degrees of freedom, the design doc's bet that a logo "in the wild" behaves like a digital overlay. Real signage also skews (6-DoF affine) and foreshortens (8-DoF perspective homography). For every query brand we built 3,368 true template→photo pairs (box-cropped template from one instance, matched against another instance of the same brand) and 5,400 false pairs, ran Lowe-ratio descriptor matching once per pair, then fit all three models to the identical correspondences — geometry is the only variable. The same three matchers also re-ranked all 175 Experiment-A queries end-to-end.

Finding. No. 6-DoF alignment does not improve search error rates: identical AUC, +2.3 pt verification recall bought with a 5.6× false-verify rate, and end-to-end AP flat (0.031 → 0.031). 8-DoF homography is worse on every aggregate — with 4-point minimal samples RANSAC overfits random correspondence sets, exactly the failure the design doc didn't anticipate when it suggested "jump straight to homography" for oblique views. The current 4-DoF choice is the right one at today's feature quality; revisit only after the feature backend improves (denser correspondences change the RANSAC economics), and then prefer adaptive gates (scale the inlier floor with model DoF) over a blanket switch.

EXPERIMENT CHow much does labeling in the Train interface matter?

Setup. 12 mid-size brands × 3 seeds. The corpus is split in half: the user votes only inside the SIM half (always on the top-ranked unlabeled item under their own current model — the honest Train-interface loop), and every curve is measured on the untouched TEST half. Four regimes get the identical vote budget: the deep-embedder detector (MLP over SigLIP), the Stage-1 MLP over VLAD, and the two-stage pipeline with and without its trained verification classifier — the last pair isolates exactly what the user's labels teach the structural stage beyond calibration.

SigLIP + MLPVLAD + MLPtwo-stage, gate only (labels never reach stage 2)two-stage + trained classifier (production)

The same 40-vote budget also buys very different discovery: voting under the SigLIP MLP surfaces 26 true instances on average; under the structural regimes, 6–7. Active learning compounds whatever the ranker already does well.

Finding. Sam's instinct is confirmed and quantified. On the structural path, the Train interface's labels do a little calibration and little else — the trained match-stat classifier's curve is statistically indistinguishable from the cold gate's (0.090 vs 0.071 AP at t=40), and ~3–5 votes capture essentially all of the benefit. When the detector is an MLP over deep embeddings, labels are the engine: cost falls monotonically for 40+ votes and shows no sign of saturating. Guidance for users: on sift_vlad datasets, vote a handful of times to calibrate, then stop; put sustained labeling effort into deep-embedder detectors.

What this says about the roadmap

The structural pipeline's ceiling is Stage 1, and it's low on real imagery. Every downstream conclusion is shaped by the fact that a VLAD-of-SIFT global vector barely retrieves small in-scene logos (top-8 brands below are the exceptions that prove it: flat, print-like, texture-dense). Three concrete moves, in order of leverage:

1 — Hybrid retrieval. Use the deep embedder for Stage 1 and keep structural verification as the re-rank/explanation layer. The plumbing exists (multi-embedder medias); at cold start it already matches SigLIP's AP while attaching inlier-box evidence to 1.1 true matches per query at an 80% true-match rate.

2 — Better local features before richer geometry. 65% of true pairs die at the descriptor-matching step, before RANSAC ever runs. That is the SuperPoint+LightGlue v2 slot the design doc already reserves — and it should be re-evaluated with this harness, because denser correspondences will also reopen the 6/8-DoF question (with an inlier floor scaled to model DoF).

3 — Keep 4-DoF and the cold gate as defaults. Both survived contact with the data: 4-DoF has the best false-verify rate at equal AUC, and the cold-start gate performs at parity with the trained classifier, which means structural search stays honest even with zero votes.

Method & caveats

Fidelity. Feature extraction, VLAD aggregation, matching, RANSAC settings, match-stat features, classifier training, thresholds, and the re-rank ordering all call the production vtscore code (or mirror it line-for-line where a cache was needed for tractability); the 6/8-DoF variants swap only the cv2 estimator on shared correspondences. MLP training uses the production auto-sized hidden layer and pinned cross-calibration folds, per the eval harness.

A serendipitous bug find — the 30th-vote transient. Both experiments show a sharp, synchronized quality dip when the label count crosses 30 (25 of 175 Experiment-A queries lose >0.3 P@10 at exactly t=30, none at t=28 or 29; the structural regime in Experiment C dips at the same count; extending a run to t=35 shows recovery by t=33). Mechanism: production auto-sizes the detector MLP's hidden layer as max(8, n_labels // 3) (vtscore/training/mlp.py), so the architecture steps 9→10 neurons at exactly 30 labels — and train_model always initializes from the same seed=42, so every dataset draws the same unlucky width-10 initialization on 8,192-d VLAD inputs until the width steps again at 33. Impact in the live app: a user's 30th–32nd vote can transiently make results worse, deterministically. Cheap fixes: average 2–3 seeds at width-change boundaries, derive the init seed from the vote set, or hysteresis on the width step. Worth a follow-up PR.

Caveats. (1) The simulated user is idealized: always votes the top item, always supplies the ground-truth box on RegionYes. Real labels are noisier, which would further favor the label-light structural regime in Experiment C. (2) Stage-2 is capped at the production top-50 shortlist; raising K would trade latency for a higher verification ceiling but cannot fix Stage-1 recall. (3) OpenLogo has label noise (co-occurring unlabeled logos), which deflates all precision numbers slightly and produces the 95+-inlier "false" pairs. (4) The cold-start hybrid uses the inlier gate only; a hybrid with votes was not measured. (5) One corpus, one media type — audio constellation fingerprints (the next structural backend) will have very different Stage-1/Stage-2 economics.
