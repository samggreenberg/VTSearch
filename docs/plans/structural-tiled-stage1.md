# Structural Stage 1 for documents: tiled VLAD in the app (#3928)

**Status:** approved by the owner 2026-09-30. M1–M4 measured the same day
and all pass (below). Build steps 1–4 are done (PR #4378).

**End to end** (`docs/experiments/2026-09-30-fullmarks-tiled-stage1-app-3928/`):

- At 5,000 pages the app's path now matches verifying every page (no
  resolvable difference at any vote count), where it found 0.17 positives by
  20 votes before.
- At 50,000 pages it finds as many (16.5 against 16.2 by 20 votes) and ranks
  0.04–0.15 AP lower, where large classes outgrow the 1,000-page shortlist.
- A vote costs 1.4 s at 5,000 pages and 4.0 s at 50,000.

**Owner's decisions (2026-09-30):**

- Run M1–M4 as gates before building.
- The projection is a **cached asset regenerated by committed code**, never
  stored in the repo ("Don't store calculated assets in the repo").
- If M4 shows K = 1,000 is too slow per vote, bring the measured numbers back
  before choosing between K = 500 and an asynchronous Stage 2.

## Why

On FullMarks, structural search is limited by Stage 1:

| FullMarks v5.0, 36 classes, mean AP | tier `s` (5k pages) | tier `m` (50k pages) |
|---|---:|---:|
| SIFT verifies every page (8,192 keypoints) | 0.83 | 0.87 |
| **Tiled VLAD, 512 dims, top 1,000 → SIFT** | **0.80** | **0.72** |
| Tiled VLAD, 512 dims, top 500 → SIFT | 0.77 | 0.67 |
| Tiled VLAD alone | 0.47 | 0.38 |
| **The app today with 10 votes** (page VLAD SVM, top 50 → SIFT) | 0.17 | — |

- The tiled-VLAD rows re-price the #3928 cell on v5.0 (2026-09-30). They clear
  the issue's bar: 84% of exhaustive at K = 2% of tier `m`.
- The app row is #4162's `a3s_production`.
- Page-level VLAD is at chance on a document page, because the text dominates
  the average. A tile vector lets a mark compete with its neighbourhood rather
  than the whole page.

## What exists already

- **`sift_vlad_doc`** (#4021) is the document embedder: 8,192 keypoints under
  the 2 MP detect cap. It has the page budget Stage 2 needs. Its Stage 1 is
  still the page VLAD.
- **Stage 2** (`structural_similarity.py`) verifies a shortlist against the
  Good votes' box templates with the inlier gate. Since #4169 no scorer is
  trained.
- **The experiment cell** (`scripts/experiments/fullmarks/stage1_cell.py`)
  already has the pieces, all numpy:
  - tile geometry: 0.25 × 0.18 of the page, stride half a tile, at least 20
    keypoints per tile;
  - a whitened-PCA `Projection`;
  - the segment-max page score.

## Design

### 1. Scope: `sift_vlad_doc` datasets only

Photos (`sift_vlad`) keep today's path until tiles are measured on BelgaLogos
(M5 below). Nothing changes for any other embedder.

### 2. Tile vectors are a new side channel, derived at load

- **Storage:** `media["tile_vectors"]` holds two arrays:
  - `vectors`: `T × 512`, fp16, L2-normalised after projection;
  - `boxes`: `T × 4`, normalised page coordinates.
- **Separate key:** it is not `patch_grid`. That key assumes a regular,
  non-overlapping grid (`patch_row_box`) and belongs to the dataset's one
  patch embedder. Overlapping tiles don't fit it, and reusing it would switch on
  the patch-space training path (`_scores_in_patch_space`).
- **No second SIFT pass:** the tiles are computed from the page's stored
  `local_features`. VLAD is aggregated over the keypoints inside each window,
  then projected.
- **Lifecycle:** a `_run_backfill_pass` in `datasets/stages/embedding.py`,
  exactly like `local_features`. It is never written to the pickle (CLAUDE.md,
  "No Persisted Vectors"), and it is re-derived on load.
- **Cost:** ~46 KiB/page, so ~2.2 GiB of RAM at 50k pages. That is next to the
  local features the same pages already hold.
- **Library home:** the tiling, projection and segment-max code moves into
  library code (`vtscore/media/structural_tiles.py`). The experiment script
  then imports it, so there is one definition.

### 3. The whitening projection: a cached asset plus the code that regenerates it

**Owner's rule (2026-09-30): calculated assets never go in the repo.** They
are cached on the GRID, and the repo holds the code that regenerates them, as
for the Pile.

- **The fit is code:** a deterministic fit command commits to the repo (library
  `vtscore/media/structural_tiles.py`, driven by
  `scripts/experiments/fullmarks/fit_tile_projection.py`).
  - It fits the 8,192 → 512 whitened PCA on a seeded sample of
    **mark-sparse** document pages (M2). The FullMarks tier-`s` all-source
    sample is the measured fit.
  - It writes `tile_projection_v1.npz` plus a `tile_projection_v1.json`
    provenance record: corpus version, tier, sample size and seed, a hash of
    the sampled page ids, the code commit, and the fitted width.
- **The asset is a cache:** it lives at
  `MODELS_DIR / "structural" / "tile_projection_v1.npz`. That is
  `$VTSEARCH_MODELS_DIR`, and on the GRID it is the pile's
  `/expscratch/$USER/vts-cache/models`.
- **Loud when absent.** A `sift_vlad_doc` dataset whose projection is missing
  or unreadable does not fall back to page VLAD without saying so:
  - the load logs a WARNING naming the file and the command that rebuilds it;
  - the dataset status reports tile Stage 1 as unavailable;
  - the eval harness refuses to run the tiled arm.

  A quiet fallback would let a study measure the wrong branch.
- **The version is part of the name** (`_v1`). A refit that changes the
  numbers gets `_v2`, so a cached `v1` never changes meaning.
- A per-dataset fit (the old option B) stays the fallback if a future corpus
  shows the cached fit does not transfer.

### 4. Stage 1 scoring: max over queries × tiles, no training

A page's Stage-1 score is the **max over (query vector, page tile)** of the
cosine. It is one matmul plus a segment max, and it reuses
`segmented_max_pool`. The query vectors are:

- **Before any vote (example sort):** each uploaded crop's VLAD, projected.
  Several crops give several queries.
- **With votes:** the crop(s), plus **each Good's box**: VLAD over the Good
  page's keypoints inside its RegionYes box, projected. A Good vote without a
  box contributes the page's best-matching tile.
- **Bads do not enter Stage 1.** This follows #4169: votes add templates, and
  nothing trained from a handful of votes has yet beaten that on this data.
  An SVM over tile rows is the alternative. M3 measures it, and it is adopted
  only if it wins.

This replaces, for `sift_vlad_doc` datasets, the linear-SVM head on page VLAD
at all three call sites:

- vote-driven `train_and_score`;
- labelset / saved-detector Find;
- `example_sort_from_paths`.

That SVM head scores 0.02–0.14 AP on FullMarks (#4162 `a3_vlad_svm`).

### 5. Shortlist size, and Stage 2 per vote

- **K:** 1,000 when the matcher has CUDA, 500 without, and never more than
  the dataset. It is passed to `structural_rerank` in place of today's 50.
  (The first draft said 2% of the dataset. That would verify only 100 pages
  at 5,000 pages, where M3 measured 1,000. The cost is per page verified,
  whatever the dataset size, so K follows the hardware (M4), not the size.)
- **The cost problem:** at 8,192 keypoints a verification costs ~160 ms per
  page per core (#3911: 25 s for 5,000 pages on 32 cores). K = 1,000 is ~160
  CPU-seconds, and today Stage 2 runs on every retrain.
- **Fix: an incremental verification cache** on `DetectorContext`, holding
  per-(template, page) `MatchStats`. It lives in memory only and dies with the
  context. A new vote then costs:
  - one new template against the shortlist;
  - plus each page newly entering the shortlist against every template.

  Adding a Good adds one template, and a stable shortlist changes little
  between votes. `SiftMatcher.verify_many` already batches one template
  against many pages, and it can use the GPU.
- **Fallback:** if M4 shows even the incremental cost is too slow on the app
  node, K drops to 500. That is 78% of exhaustive at tier `m`, against 84%.

### 6. Threshold

The inlier gate stays (#4169). At 8,192 keypoints it over-accepts: F1
0.14–0.26 on FullMarks (#4367). That calibration work comes after this and is
tracked there, not here.

### 7. The eval default arm is the app

The FullMarks harness (`vote_curve.py`) gets an arm that calls the library's
tile scoring and `structural_rerank` directly (delegation, not a copy). A
`check-eval-app-sync.py` mirror is added if any piece has to be ported.

## Measured (2026-09-30)

Run directory: `/expscratch/sgreenberg/stage1-v50-3928/`. Scripts:
`stage1_cell.py --from-compact / --fit-sources`, `stage1_votes.py` and
`bench_verify.py`, all in `scripts/experiments/fullmarks/`.

**M1: PASS.** Tiles built from the compacted features the app stores (fp16
keypoints, uint8 descriptors) rank like the float extraction.

- Tier `s`, 36 classes, K = 1,000: mean AP 0.798 against 0.799.
- Mean paired difference −0.001; the largest single-class gap is 0.03.
- The float rebuild reproduces the 2026-09-18 cell exactly (0.799).

**M3: max over queries wins; the SVM loses.** This is the shared vote sequence
(#4162: the query crop's top *v*, labelled from ground truth), scored on the
unlabelled remainder.

| 10 votes | Stage-1 AP, `s` | → SIFT K=1,000, `s` | Stage-1 AP, `m` | → SIFT K=1,000, `m` | → SIFT K=500, `m` |
|---|---:|---:|---:|---:|---:|
| crop only | 0.38 | 0.82 | 0.28 | 0.66 | 0.60 |
| **max over crop + Good boxes** | **0.68** | **0.87** | **0.59** | **0.84** | **0.79** |
| SVM over tile rows (Bads flood) | 0.49 | 0.86 | 0.38 | 0.73 | 0.68 |

- **Max over queries vs crop only, tier `m`:** Stage 1 +0.31
  [+0.22, +0.41], pipeline +0.18 [+0.11, +0.26].
- **SVM vs max over queries, tier `m`:** Stage 1 −0.21 [−0.32, −0.10],
  pipeline −0.11 [−0.18, −0.05].
- For reference, every page verified with max over templates scores 0.87 at
  both tiers after 10 votes (#4162), and the app today scores 0.17.
- **Caveat:** the vote sequence comes from the exhaustive ranking, which is
  optimistic for Stage 1. The comparison between arms is still fair.

**M4: PASS on a GPU.** This is `verify_many` for one template against 1,000
pages at 8,192 keypoints (median 5,904 per page).

| | L40S + 8 CPUs | 8 CPUs, no GPU |
|---|---:|---:|
| median Good-box template (138–485 kp) | **0.85 s** | 5.9 s |
| query crop (1,209 kp) | 1.3 s | 20 s |

- The batched ratio test dominates (crop: 1.05 s of 1.28 on the GPU, 19.6 of
  20 on the CPU); RANSAC is small.
- With the incremental cache, a vote costs ~1 s on the GPU at K = 1,000, so the
  owner's K-vs-async question does not arise on a GPU node.
- **Two costs remain exposed:**
  - **Cold start** is ~1 s per template. Reopening a saved detector with 20
    Goods costs ~20 s once per process.
  - **A CPU-only deployment** costs ~6 s per template. That one needs K = 500
    or a template cap. The build picks K from whether the matcher has CUDA.

**M2: PASS, with a rule for the fit.** Each cell's projection was fit on
only some FullMarks sources, then scored against the all-source fit (tier `s`,
paired over classes, 95% intervals):

| projection fit on | unseen sources, K = 1,000 | own sources, K = 1,000 | own sources, Stage 1 alone |
|---|---:|---:|---:|
| SPODS + StaVer | +0.03 [−0.02, +0.11] | −0.02 [−0.04, +0.01] | **−0.17** [−0.25, −0.10] |
| Tobacco800 + UCSF | +0.00 [−0.01, +0.01] | −0.02 [−0.07, +0.06] | −0.02 [−0.06, +0.01] |

- **Transfer holds.** The unseen sources lose nothing.
- **What does hurt is fitting on pages dense with the very marks being
  searched.** The SPODS + StaVer fit costs those sources' own classes 0.17 of
  Stage-1 AP. Their stamps and logos repeat across the fitting pages, and
  whitening flattens the directions they occupy.
- **Rule for the cached asset:** fit on mark-sparse document pages. FullMarks'
  distractor-dominated all-source tier-`s` sample is such a fit, and it is the
  one measured above. Record the fitting pages' provenance beside the asset.


## Build order (after sign-off and M1–M4)

1. `vtscore/media/structural_tiles.py`: the tiling, projection, segment max and
   the deterministic fit, with tests. Also `fit_tile_projection.py`, and the v1
   asset built into the GRID models cache. `stage1_cell.py` is re-pointed at
   it.
2. The `tile_vectors` back-fill pass for `sift_vlad_doc`, with tests (derive,
   reload, `combine_datasets` pops it).
3. Tile Stage 1 at the three call sites, plus K, plus the verification cache,
   with tests.
4. The eval harness arm, an end-to-end replay on FullMarks tier `s`/`m`, and a
   report.
5. Then a State of the App: Documents review (#4159's skill, "Document Logo"
   report) on the shipped path.

## Known limits this does not fix

- `tobacco800/logo_cgr96c00_1`: a 117-keypoint query crop that no tile vector
  finds (Stage-1 recall 0).
- The two-crest Philip Morris class, which one query crop can only half-find.
  The multiple query crops of #3949 are the lever.
- Local-feature RAM for a tier-`l`-sized document dataset (see
  `embedder_sift_vlad_doc.py`). Tiles add ~5% to it.
