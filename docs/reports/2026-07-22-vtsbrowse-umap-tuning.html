Tuning the map: per-embedder UMAP defaults for VTSBrowse

VTSBrowse turns a whole collection into a single zoomable map by squashing each item's embedding down to an (x, y) point with UMAP. This is a from-scratch empirical study of how UMAP's dials should be set — and it finds that the best settings depend on which embedder produced the numbers, and that one long-standing default is quietly costing layout quality.

Why this study

VTSBrowse's map is built in two stages. Stage 1 runs UMAP on each item's embedding — the long list of numbers a neural network uses to represent its content — and squashes those hundreds or thousands of numbers down to two, an (x, y) point on screen, placing similar items near each other. Until now VTSBrowse used one fixed setting of UMAP's dials for everything, regardless of which model produced the embeddings. This study asks two questions the codebase had left open: should those dials be set per embedder, and should the cosmetic compaction step stay switched on?

The three dials

  • n_neighbors — how much of the collection UMAP consults when placing each item. Small values (5–15) capture tight local lookalikes and make many small islands; large values (100–200) weigh the global arrangement into a few broad continents. The most consequential dial.
  • min_dist — how tightly items may pack within a cluster. Changes how the map looks but not who counts as a neighbor, so we expect a weaker effect.
  • compaction (on/off) — a post-step that slides UMAP's scattered clusters together like puzzle pieces (each moving rigidly, keeping its shape) to close the empty "oceans" UMAP leaves between islands, so the canvas isn't mostly dead space after zoom-to-fit.

The four embedders in scope — CLAP (audio) and CLIP, SigLIP, SigLIP-L (images) — output vectors of different sizes (512, 512, 768, 1152) with different geometry, which is exactly why one-size dials might leave quality on the table.

How we scored a map

A good map keeps items of the same kind together. To measure that objectively we used datasets that ship with a taxonomy — a labeled tree of categories (ESC-50's 50 sounds group into 5 families; iNaturalist's species nest into a 6-level biological tree). For every category we ask: do that category's points sit among their own kind on the map? Formally, for each point we take its 20 nearest map-neighbors and measure how strongly same-category points are surrounded by same-category neighbors — summarized as an AUROC from 0.5 (no separation) to 1.0 (a clean boundary), averaged over every category and every level of the tree.

Two refinements make the number trustworthy. Ceiling normalization: some classes are hard to separate even in the original high-dimensional space, so we compute the same score there and report the ratio (map ÷ original). A ratio near 1.0 means the projection kept essentially all the separability there was to keep — and that ratio is precisely what the UMAP dials control. Guard metrics: a layout could fake purity by shattering the space, so label-free checks (trustworthiness, continuity, neighbor-recall) veto any setting that wins on separability while mangling local structure. Because production runs UMAP unseeded, we also fit every setting with 3 seeds and track run-to-run stability. Up is good on every metric here.

Setup

Grid: n_neighbors ∈ {5,10,15,30,50,100,200} × min_dist ∈ {0,0.05,0.1,0.25,0.5} × compact ∈ {off,on} × 3 seeds, over 23 embedded (dataset × embedder) matrices — audio (ESC-50 S/M/L, GTZAN, FSD50K) and image (Caltech-256 S/M, Places365 S/M/L, iNaturalist). Compaction is a free axis: both variants are scored from the same fit. Two deep-taxonomy sets — FSD50K (AudioSet ontology) and an iNaturalist subset (156 species across 3 kingdoms) — were built for this study.

Q1. The best n_neighbors depends on the embedder

Across the whole grid, separability peaks at small n_neighbors and falls steadily as the dial grows — and the peak sits in a slightly different place for audio than for images. CLAP is happiest around 10–15; all three image embedders peak at 10, with CLIP the most sensitive (it drops off fastest). Nobody benefits from large neighborhoods: at n_neighbors = 200 every embedder is measurably worse, and images lose the most.

Q2. The optimum tracks the embedder, not the dataset size

A natural worry: maybe the best n_neighbors just scales with how many items you have. It doesn't. The Places365 curves above span 5,000 → 21,000 images and lie almost on top of each other — the peak stays put as N grows. So the deliverable is a per-embedder constant, not a formula in N. Stability tells the same story from another angle: small-to-mid neighborhoods are not only more separable but more reproducible run-to-run, while at n_neighbors = 200 two unseeded fits share only about half their neighbors — a real hazard for a production path that never seeds.

Q3. Compaction consistently costs layout quality

Compaction was added for readability — closing the empty oceans so the canvas fills the frame. But sliding clusters until they nearly touch pushes neighboring classes into contact, and the metrics see it everywhere: every dataset × embedder loses separability under compaction, and the structural guards drop 5–6%. The cost grows with the layout's density — small, easy sets barely notice; the 21k-image Places365 layouts lose the most.

Verdict

The hit is consistent and material, so the metric-driven call is to turn compaction off by default (it remains a per-media-type server setting, so it's one toggle to restore). The eyeball above shows the tradeoff plainly: raw UMAP keeps the biological classes as clean, separated islands; compaction fills the frame but smears the boundaries. The better long-term fix is to rework compact_layout to keep a minimum margin between islands — closing oceans without the bleed — which is filed as follow-up.

The layouts, by eye

The scores line up with what you see. As n_neighbors grows, a projection moves from a scatter of tiny fragments (over-local) toward a few coherent continents; the sweet spot keeps genuine sub-groups distinct without dissolving them into the background.

What shipped

The chosen defaults are wired in as a per-embedder map, consulted where the global PROJECTION_N_NEIGHBORS / PROJECTION_MIN_DIST were read, keyed off the dataset's primary embedder; the existing ServerSettings still override, and the persisted projection is already keyed on effective params so new defaults force a clean recompute. The compaction default flips to off. A CPU-backend re-fit of these exact values on umap-learn reproduced the ranking on all 23 embedded sets — the tuned settings beat the current default by +2.6% separability on average (per embedder: CLIP +3.2%, SigLIP +3.0%, SigLIP-L +2.8%, CLAP +1.2%) — so one defaults table is safe for both the GPU (cuML) and CPU projection paths.

# vtscore/config.py — consulted by the projection route, per primary embedder
PROJECTION_DEFAULTS_BY_EMBEDDER = {
    # embedder:     (n_neighbors, min_dist)
    "clap":     (15, 0.10),   # audio: flat peak 10–30
    "clip":     (10, 0.05),   # image: most n_neighbors-sensitive
    "siglip":   (10, 0.05),
    "siglip_l": (10, 0.05),
}
# fit_projection(..., compact=False)  — verdict applied; overridable per media type

Take-aways

  • Set n_neighbors per embedder: 10 for the image embedders, 15 for CLAP. The old global 15 was fine for audio but slightly high for images.
  • Never go large: n_neighbors ≥ 100 hurts every embedder on both separability and stability — the clearest, most actionable result.
  • min_dist barely matters for grouping; images prefer it a touch lower (0.05), which also reads as tighter clusters. It's the one dial safe to decide on looks.
  • Compaction trades layout fidelity for screen-fill — a consistent 2%/6% cost. Off by default now; worth reworking to keep the readability win without the bleed.
  • The optimum is a per-embedder constant, not a function of dataset size.

Method & reproduction

The harness lives in scripts/experiments/umap_params/ (dev-only, outside the shipped package). It embeds each (dataset × embedder) once and caches the matrix, then re-fits UMAP cheaply over the cache for the whole grid; the metric is pure NumPy/scikit-learn. Winners were re-fit on the CPU umap-learn backend to confirm the ranking transfers from the GPU cuML path that production uses. The core of the separability metric:

# metric.py — AUROC that same-class points have more same-class map-neighbors
def node_auroc(knn_idx, mask):
    frac = mask[knn_idx].mean(axis=1)          # in-class neighbor fraction
    return roc_auc_score(mask, frac)           # 1.0 = clean boundary at k
# ratio = (mean node AUROC on 2-D) / (same on the original embedding)
