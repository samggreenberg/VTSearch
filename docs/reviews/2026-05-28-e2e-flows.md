# End-to-end flow walkthrough — 2026-05-28

Task 3 of [docs/plans/browser-vision-testing.md](../plans/browser-vision-testing.md).
Driven via the Playwright MCP browser at 1440×900, light theme (except where
Flow 4 deliberately switches to dark to test the round-trip). The app ran
against an empty `data/` (existing `data/` moved aside to `data.task2-backup/`;
embedder models + synthetic generator cache were symlinked back in so
imports could run without re-downloading SigLIP).

Findings are tagged `U#` (UX friction) and reuse `O#` from prior reviews
where the same observability gap reappears. Severities are Low / Med / High.

## Flow 1 — Train a new detector

**Goal**: import → vote → save → re-load → autodetect → export.

**Steps**:

1. Empty dashboard (`01-flow1-empty-dashboard.png`).
2. Click `+` on Datasets → Add Dataset picker opens with Services / Server /
   Local / Demo tabs (`02-flow1-importer-picker.png`).
3. Demo → Synthetic Media → set Size = 50, Name = `shapes-train`, Import
   (`03-flow1-synthetic-form.png`).
4. Embedder cold-load and per-file embed visible in row, with Cancel
   affordance (`04-flow1-dataset-loaded.png`).
5. Dataset ready: 50 items, Image, Loaded ✓; bottom Train CTA enables
   (`05-flow1-dataset-ready.png`).
6. Click `+` on Detectors → New Detector modal (Blank / Trained tabs,
   Media Type locked to Image, text-or-image example, name)
   (`06-flow1-new-detector-modal.png`).
7. Text example = `red circle`, name = `red-circle`, Create. Detector row
   appears with `# Training = 0`, `Last Trained = -`, `Loaded ✗`. Find hint:
   "Selected detector has no training labels." (`07-flow1-detector-created.png`)
8. Train → enters autopilot's "Find Initial Goods" stage at 0/3
   (`08-flow1-train-initial.png`).
9. Vote with ← / → for ~17 items, mostly judging by whether a red circle
   was present (`09-flow1-after-vote-1.png`).
10. Autopilot ticks Find Initial Goods + Find Initial Bads off and lands on
    "Refine Boundary" with 17 labels (Goods 7, Bads 10). Side panels show
    pinned thumbnails of each labeled item (`10-flow1-after-many-votes.png`).
11. Back to Dashboard. Detector now shows `# Training = 17`,
    `Last Trained = 2026-05-28 05:06`, `Loaded ✓`, Autorun ✗; Find button
    enables (`11-flow1-dashboard-after-train.png`).
12. Click Find → Find view loads with 50 ranked items, score-bar minimap,
    selected image preview, and Goods (41) / Bads (9) prediction panels on
    the right (`12-flow1-find-view.png`).
13. Click Export → modal with Categories (All/Good/Bad/Corrections),
    Columns (toggleable), Preview (all 50 rows), Delimiter (comma/tab/pipe/
    semicolon), and destination buttons (Clipboard, Email, Server CSV,
    Server JSON, Webhook) (`13-flow1-export-picker.png`).
14. Click Server JSON File → expands an inline form with `Save to (server
    path)` pre-filled `data/red-circle-shapes-train.json` (auto-derived from
    detector + dataset names) (`14-flow1-server-json-form.png`).
15. Save → 26 KB JSON written, no error toast (`15-flow1-export-saved.png`).

### Findings — Flow 1

- **U1 (Med, recurring from edge-states audit)** — Nav-bar pickers say
  "Select a dataset" / "Select a detector" right after import/create, even
  though the system has clearly auto-selected the new row (Train CTA
  enables, row is highlighted). The nav only catches up once the user
  navigates into Train. Reconfirmed in step 7 here.
  Screenshot: `07-flow1-detector-created.png`.

- **U6 (Low) — `Create` is disabled until a text or image example is
  supplied, with no inline help explaining the requirement.** Filling in
  only Detector Name + leaving both examples blank leaves Create grayed
  out; the user has to guess that an example is also required. Suggested
  fix: a "required" marker on at least one of Text Example / Image Example,
  or a "Provide a text or image example" hint when both are empty.
  Screenshot: `06-flow1-new-detector-modal.png` (Create disabled with no
  message).

- **U7 (Low) — `# Training = 0` and `Loaded ✗` on a freshly-created
  detector reads as "broken" instead of "awaiting labels".** Same as U3 in
  the edge-states audit; reaffirmed here.

- **U8 (Med) — Find-view right-rail labels are ambiguous: `Goods (41)` /
  `Bads (9)` after voting on only 17 items.** The numbers include the
  autopilot's predicted classifications, not just the user's labels. The
  heading reads as labeled counts, but the count is actually labeled +
  predicted. Either rename to "Predicted Good / Predicted Bad" in the
  Find view, or visually distinguish predicted from user-confirmed items
  (the thumbnails do differ subtly but the count headers are the same as
  the Train view's labeled counts, which is what causes the confusion).
  Screenshot: `12-flow1-find-view.png`.

- **No friction (positive)** — Export's auto-derived filename
  (`data/red-circle-shapes-train.json`) and the inline expansion of each
  destination's form (rather than yet-another modal) are smooth. The
  back chevron on the destination form sub-modals is correctly placed
  per CLAUDE.md "Nested-modal back buttons" rule (see Flow 4 for a clear
  shot).

## Flow 2 — Use an existing detector

**Goal**: import a different compatible dataset → load the saved detector
from Flow 1 → autodetect → spot-check → export.

**Steps**:

1. Dashboard with shapes-train + red-circle detector still loaded.
2. Click `+` Import a new dataset → Demo → Synthetic Media → Size = 30,
   Name = `shapes-test`, Import. Dataset embeds and lands (`16-flow2-second-dataset-loaded.png`).
3. New dataset is auto-selected (table row highlighted, checkmark). The
   `red-circle` detector remains selected. Find CTA stays enabled — no
   manual "switch to new dataset" / "apply detector" step required.
4. Click Find → loads ranked Find view for shapes-test scored by red-circle.
   30 items in the left minimap with score bars, right rail shows
   `Goods (30)` / `Bads (0)` (the detector trained on shapes-train confidently
   predicts every shapes-test item as positive — partly an artefact of the
   intentionally noisy labeling in Flow 1, partly because synthetic shapes
   are visually similar across runs) (`17-flow2-find-on-new-dataset.png`).
5. Spot-checking high-score and low-score items is just clicking rows in
   the left list; no separate UI was needed for this. The score-bar
   minimap doubles as the spot-check entry point.

(Export was skipped — same flow as Flow 1.)

### Findings — Flow 2

- **O1 (High, recurring from edge-states audit, **amplified**) — Cross-
  dataset media-id leakage produces 20 simultaneous 404s on opening Find
  against a smaller dataset.** When the active dataset shrinks (Flow 1
  shapes-train was 50 items; shapes-test is 30), the Find view sends 20
  `/api/medias/{31..50}/image` requests carrying the previous dataset's
  highest IDs — all 404. The UI does not surface the failure (no toast,
  no broken thumbnail), so users wouldn't notice, but the network panel
  is noisy and the requests waste server work. Same root cause as the
  edge-states audit's O1 (sub-view state isn't reset when the active
  dataset changes); this run shows it scales with the size delta.
  Screenshot: `17-flow2-find-on-new-dataset.png` (console errors visible
  in the captured page metadata).

- **U9 (Low) — "Find" is the only affordance for applying a trained
  detector to a new dataset.** No autodetect-specific UI; the user is
  expected to figure out that Find = "score this dataset with the
  selected detector". The CLI exposes `--autodetect` (per CLAUDE.md), so
  the concept exists; the dashboard could echo it (e.g. button label
  "Find · Autodetect" or a hover-tooltip on Find that says "Score this
  dataset using the selected detector"). Particularly relevant on Flow 2,
  where the user's mental model is "apply existing detector," not "find
  matches".

- **No friction (positive)** — Re-applying a detector to a fresh dataset
  is genuinely one click (Import → Find). The auto-rerank happens without
  any modal/confirmation.

## Flow 3 — Multi-media import

**Goal (per plan)**: use a multi-media importer with ≥2 source rows
(e.g. an `image` output dataset with `video → video2image` and
`document → document2image` source rows).

**What actually exists**: there is no importer in the picker that takes
multiple source rows / per-row converters. The Add Dataset picker has
Services (currently empty: "No importers in this category."), Server
(Folder, Files), Local (Folder, Files), and Demo (Downloaded Media,
Synthetic Media). Each importer is single-source. The closest UX in the
current build is the **Combine Datasets** action on the dashboard
(merges already-imported pickle datasets of the same media type, deduped
by content hash). I exercised that as the nearest available approximation.

**Steps**:

1. Open Add Dataset → Services tab is empty (`18-flow3-services-tab.png`).
2. Local tab shows Folder / Files only (`19-flow3-local-tab.png`).
3. Close modal, select both `shapes-train` (50) and `shapes-test` (30) via
   the row select-checkboxes. The previously-disabled "Combine selected
   datasets" toolbar button enables (`20-flow3-two-datasets-selected.png`).
4. Combine → Combine Datasets modal: auto-named "shapes-train + shapes-test",
   shows a source list with per-row remove `×`, totals row "2 datasets /
   Image / 80", and helper text: "The combined dataset will contain up to
   80 Image items (duplicates removed automatically)."
   (`21-flow3-combine-modal.png`).
5. Combine → new dataset "shapes-train + shapes-test" appears with 50
   items (dedup collapsed the merged 80 down to 50 because the synthetic
   generator produces the same items at the same seed)
   (`22-flow3-after-combine.png`).

### Findings — Flow 3

- **U10 (High) — The multi-media import flow the plan asks for does not
  exist in the current build.** No importer in any of the four picker
  tabs (Services / Server / Local / Demo) accepts multiple source rows
  with per-source converters. The Combine Datasets feature is adjacent
  but different — it merges two existing pickle datasets of the same
  media type rather than letting one import draw from heterogeneous
  source types and convert them all to a single output type. Either the
  plan needs updating to reflect what the UI offers, or this is a real
  feature gap. Recommend updating the plan first; if the feature is
  actually planned, the plan file should track its status (`Open
  follow-ups: multi-media importer not yet implemented`).

- **U11 (Low) — Combine modal's "up to 80 items" prediction is
  technically accurate but practically misleading on synthetic data.**
  The two source datasets used the same synthetic seed, so deduplication
  collapsed all 80 candidates back down to 50. The modal warned "up to"
  and "duplicates removed automatically", so this is honest, but the
  resulting combined dataset is identical to the larger of the two
  sources and the user might not realize that's what happened.
  Suggested fix: after combine, surface a one-line summary toast like
  "Combined 2 datasets into 1 (50 unique items kept, 30 duplicates
  dropped)" rather than silently landing back on the dashboard.

- **No friction (positive)** — The Combine modal itself is clear: the
  per-row source list with `×` to remove, the totals row, and the
  helper-text dedup warning are all the right shape. The auto-derived
  name + correct media-type lock are also good.

## Flow 4 — Settings round-trip

**Goal**: change a few settings → export → reset → import → verify
restored.

**Steps**:

1. Open Settings → Appearance. Change Theme to Dark, change Image · Left
   Side · Grid Icon Size to XL. UI re-themes immediately
   (`23-flow4-settings-changed-dark.png`).
2. Click Export at the footer → Export Settings modal with two
   destinations: Local JSON File (download) and Server JSON File (write
   to disk) (`24-flow4-settings-export-modal.png`).
3. Click Server JSON File → nested form opens with `← Back` chevron,
   pre-filled path `data/settings_backup.json`, Cancel / Export buttons
   (`25-flow4-settings-export-server.png`).
4. Export → 3 KB JSON written, includes `"theme": "dark"`,
   `view_mode_left`, etc. (`26-flow4-settings-exported.png`).
5. Click Default → confirmation dialog: "Reset all settings to factory
   defaults? Your current preferences (appearance, view modes, autopilot,
   calibration, and other per-user settings) will be overwritten and
   cannot be recovered." with Cancel / Reset (`27-flow4-settings-defaulted.png`).
6. Reset → Theme reverts to System (light), Grid Icon Size both back to M;
   UI re-themes to light (`28-flow4-after-reset.png`).
7. Click Import → Import Settings picker with the same two destinations
   (Local / Server). Server JSON File → nested form with `← Back`
   chevron and `Path or URL` input (`29-flow4-settings-import-picker.png`,
   `30-flow4-settings-import-form.png`).
8. Enter `data/settings_backup.json` → Import → settings re-applied,
   Theme back to Dark, Grid Icon Size left back to XL, UI re-themes
   (`31-flow4-after-import.png`).

### Findings — Flow 4

- **No friction (positive)** — Settings round-trip works end-to-end.
  Reset prompts an explicit confirmation with the right language ("cannot
  be recovered"). Both Export and Import use a destination-picker
  followed by a back-chevron'd nested form, matching the CLAUDE.md
  pattern. Theme and Grid Icon Size are correctly serialized to and from
  JSON. The same Local / Server destination set is offered on both
  Export and Import, which keeps the mental model symmetric.

- **U12 (Low) — Export and Import destination cards have no per-card
  hover state or affordance** to suggest "this card is clickable as a
  whole." Users have to discover by clicking. Adding the standard
  card-hover lift / cursor-pointer would close the gap. (Did not
  screenshot specifically — visible in `24-flow4-settings-export-modal.png`
  and `29-flow4-settings-import-picker.png`.)

- **U13 (Med) — Default-reset wipes settings without explicitly
  reminding the user that Export exists first.** The confirmation dialog
  warns "cannot be recovered", but doesn't suggest "Export your current
  settings first if you'd like to keep them." A user who hasn't already
  exported (the canonical case for first-time use) loses everything with
  no in-flow opportunity to back up. Suggested fix: add a secondary
  link in the confirmation: "Export current settings before resetting."
  Screenshot: `27-flow4-settings-defaulted.png`.

## Cross-flow patterns

- **U1 / U7 (recurring) — Pre-action selection state is ambiguous.** The
  nav-bar pickers, the dashboard row highlights, and the bottom CTA hint
  text all disagree about whether something is "selected" right after
  creation/import. This was logged in the edge-states audit (U1, U3) and
  recurs here in Flow 1 (step 7) and Flow 2 (step 3). The fix is one
  thing — make the active-dataset / active-detector observables update
  synchronously with the table-row selection, instead of waiting for a
  downstream view to re-read them. Worth a single PR.

- **U6 / U2 (recurring across audits) — Primary actions disable silently
  when a required field is missing.** Edge-states audit's U2 was the
  server-folder importer; this audit's U6 is the new-detector Create
  button. Both cases: button grays out, no inline hint about which field
  is the blocker. A repo-wide rule of thumb "if a primary action is
  disabled, show why" would catch this whole class.

- **O1 (recurring, amplified) — Sub-views don't reset when the active
  dataset changes.** Edge-states audit saw 1 stale-id 404; this audit's
  Flow 2 sees 20. The Find view (and probably any other detector-aware
  sub-view) should drop or remap its in-flight requests when the active
  dataset id changes, not just re-render against the new id.

- **Positive — modals consistently use `← Back` (top-left chevron) for
  retreats from nested sub-forms** (Flow 4's Server JSON File form,
  the multiple flows' import/export pickers). The Back-vs-Cancel
  semantic in CLAUDE.md is being followed cleanly across the surfaces
  exercised in this audit.

- **Positive — destination + name pre-derivation is consistent across
  the export surfaces** (Flow 1: `data/red-circle-shapes-train.json`,
  Flow 4: `data/settings_backup.json`). The user almost never has to
  type a path from scratch, which is the right default for a
  desktop-only tool.

- **Process note — the plan's Flow 3 is mis-specified for the current
  build.** This is the second time a vision-testing run has surfaced a
  gap between the plan and the actual UI (the edge-states audit hit a
  similar mismatch with `solo_media_type`'s effect on the import
  picker). When updating `browser-vision-testing.md`, both should be
  flagged so the next run starts from accurate expectations.
